# 火山中英配音导演

你负责导演和中文校对；脚本负责候选扫描、阅读稿、请求和音频，不另调规划或审稿模型。支持中文、英文及中英混读，中文默认普通话。保留用户原文、指定音色与角色；引用不自动增加角色。英文品牌、型号和技术词保留原文直接提交，不自动翻译或转成中文音译，不改写数字或添加语气词。缩写和型号优先使用可配置发音表；日期、金额、编号的特殊读法需遵从用户意图，必要的口播改写要明确记录。

## 实际流程

脚本路径从本 skill 目录解析，作品存到用户项目目录。Python 3.10+，唯一运行依赖为 pypinyin，推荐 `uv run scripts/tts.py`（自动使用脚本声明的依赖）。依赖与缓存使用内部 SSD，不把虚拟环境放到外置项目卷。

1. 用 `prepare --text-file 原稿.txt --out plan.json` 得到草稿。自动建议来自词典，**不代表完成语境校对**。按自然段或角色调整 `clips`，不要无故逐句切碎；单段上限 500 字是本工具的本地策略，超长要明确分段，不能截断原文。角色可各自设置 `voice`、语音指令 `direction`、引用上文 `reference_text`、方言 `explicit_dialect`、`speech_rate`、`pause_after_ms` 和可选的段落标识 `section_id`。从用户原稿或对话中选必要前文填入 `reference_text`，不编造上文，不自动跨场景引用。默认音色只是候选，实际权限以用户控制台为准。
2. 检查全部多音字候选，以及姓氏、地名、专名、古文、轻声和“一／不”的变调。结合上下文修正 `readings`，用词组替换单字标注，例如“银行”的 `yin2 hang2` 与“行走”的 `xing2 zou3`；`start` 是段内从零开始的 Python 字符索引，`text` 必须精确匹配原文。已判断的项标 `reviewed`，未知项保留 `pending`，只询问真正缺少的信息。普通词可由你校对，无须让用户逐字批准；私人姓名等无法确定的读音不能猜。扫描项默认 `delivery: native`，校对展示与强制纠音分开；普通词不因为存在古音候选就全部强制改读音。需要纠音时明确选 `dictionary`、`instruction` 或 `spoken_alias`，详见 [纠音投递方式](references/usage.md#纠音投递方式)。
3. `preview --plan plan.json --out 阅读稿目录` 生成 HTML 与 Markdown。**向用户展示阅读稿**，在正文中标出多音字和读音，同时列出语境、建议或已校对状态、备选读音及理由，并分别展示语音指令、引用上文、语速和方言。无需密钥或合成。HTML 用 ruby 标注，Markdown 用“行〔háng〕”形式。这些注释与导演说明不进入朗读文本；不能把页面里带注音的内容复制到 `text`。
4. 用户只要审稿或选音色时到这里即可。按用户要求试听或生成时，先读 [运行与计划格式](references/usage.md)，执行 `render --dry-run` 验证完整请求，再按已授权的文本、目的地和调用范围生成。首次调用说明片段数、字符数和可能收费；已有授权不逐段重复询问。密钥只取运行时 `VOLC_TTS_API_KEY`，不读取其他项目的私有配置，不复制、打印或存储密钥。
5. 交付 `final.wav`、阅读稿、计划与实际调用状态；字幕默认开启，同时交付每段 `*.words.json`、全片 `timeline.json` 和句级 `final.srt`，详见 [逐字时间戳与字幕](#逐字时间戳与字幕)。有试听工具才声称听过；结构检查不证明读音或演绎正确。用户反馈改词、改读音或音色时只改受影响段；已完成的相同请求复用本地音频和字幕，停顿调整只重新拼接并更新时间线。连接断开可能已计费，不自动重试或换供应商。

## 已有克隆音色

用户提供 `S_` ID 时，可用 `prepare --voice S_xWSg2NNT1 --resource-id seed-icl-2.0`。本工具默认将 `S_` 选择为复刻 2.0 资源，**不是从前缀推断训练代际**；只支持已训练完成且账号有合成权限的音色，不上传录音、不训练、不升级、不自动试旧资源。克隆草稿默认 `direction` 为空，由导演按具体能力选择控制字段，不自动附普通话风格指令，也不静默删除用户已有指令。

每段可显式设置 `resource_id`；`zh_` 只接 `seed-tts-2.0`，`S_` 只接 `seed-icl-2.0`。阅读稿和 dry-run 展示有效资源，合成目录保存无凭据的 `routes.json`。先校对并核对资源，再按授权试听一个代表短句；失败不自动重试或换代际。指令、上文、纠音和方言能力不能只凭 `S_` 或一次成功判定。详见 [已有克隆音色](references/usage.md#已有克隆音色)。

## 逐字时间戳与字幕

- TTS 2.0 / ICL 2.0 使用 `req_params.audio_params.enable_subtitle`，默认开启；不要使用 TTS 1.0 的 `enable_timestamp`。计划顶层和 clip 的 `enable_subtitle` 必须为布尔值，片段优先；render 的 `--timestamps / --no-timestamps` 覆盖计划。dry-run 只生成请求与路由，不联网或读取密钥。
- HTTP 字幕帧在顶层 `sentence`，包含 `text / words / phonemes`；字幕可能晚于音频，脚本等待完成码并读到响应 EOF。需要核对实际响应时使用 `--debug-stream`，仅输出脱敏响应帧，不打印凭据、请求头或音频数据。
- 每段 WAV 旁保存 `<hash>.words.json`，含 `text`、逐字 `words` 与句级 `sentences`。`startTime / endTime` 是相对该请求起点的浮点秒，保留服务端 `word` 与 `confidence`；标点可能附在字上，字幕可能体现实际可听别名或数字规范化，不能强称与原稿逐字一致。
- `timeline.json` 列出每段在 `final.wav` 中的 `offset`、时长、段后停顿、文件和字幕状态；顶层 `words / sentences` 使用含段间停顿的全片秒时间并附 clip ID。偏移由 PCM 采样数累计，包含最后片段配置的段后停顿。`final.srt` 按句输出，用所属字词的真实首尾时间；跨句 token 合并字幕、零时长标点只归属一个正时长句子。规范化文字仅在锚点可唯一确定句界时分句，否则保留服务端整句，不猜内部时间。
- `explicit_dialect` 或片段 `enable_latex_tn: true` 会关闭该请求的字幕；接口无字幕或字幕无效时也正常交付音频。manifest 记录 `words_file`、`timestamps: false` 和原因；空 words 文件区分明确降级与缓存丢失。部分片段有字幕时保留有效结果，但 timeline 顶层 `timestamps` 为 false，不能宣称全片字幕完整。
- 字幕开关参与请求指纹。开启字幕遇到已有缓存却缺 `words.json` 时，在任何真实调用前停止并提示需要重新渲染；先核对费用和授权，再用新输出目录生成，不静默忽略或自动重发。接口未返回字幕的空结果可缓存，不自动重复尝试；但 manifest 记录有字幕而 sidecar 变空须明确拒绝。累计帧修订只有在能可靠调和时保留最新字词和时间，含糊重叠降级。完整 WAV 分块预检、流式拼接；改停顿只更新拼接、时间线与 SRT，不重写未变化的 manifest，真实调用的状态仍即时落盘。
- 时间戳精度属于服务端能力；本工具负责完整接收、保留返回字词的原始时间和置信度、正确计算拼接偏移及导出格式，不校正对齐、不裁剪音频、不引入强制对齐模型。`timestamps: true` 不表示精确口型保证。真实测试核对接口值与落盘值一致；末字 `endTime` 与 WAV 时长差（例如 0.3 秒参考值）、低置信度等只作为供应商质量观察，不单独判定本工具调用或导出失败。如实交付原始结果，不自动重试或修正。

详见 [运行与计划格式](references/usage.md#逐字时间戳与字幕)。

## 中英混读与发音表

- 含英文的 `prepare` 默认加载 [pronunciations.json](references/pronunciations.json)，可用 `--pronunciation-table 自定义.json` 换表；内容快照保存在计划顶层 `pronunciation_table`，preview/render 不重新读取外部表。旧计划缺此字段时不自动套用新规则。
- 英语词保留在 `req_params.text`。Anthropic / Claude / Haiku 的 `an-THROP-ik / klawd / HIGH-koo` 是英语发音提示，通过 `context_texts` 首条提交，不是 IPA/CMU 或确定性音素控制。DeepSeek、OpenAI 等用原生英语，不能声称提示必然生效。
- KV / API / MLA / GPU / IPO 使用英文逐字母服务端文本转写，S-1 读 `S one`。`models` 显式列出型号，`decimal_point` 可设为 `point / 点`；不自动改所有日期、价格或 IP。字典全局最长匹配，源词最多 9 字符、无空格；检查子串误改和汉字校对冲突，必要时明确完整词组或自然拆段，不静默跳过错误。
- 官方音色列表确认 `zh_male_youyoujunzi_uranus_bigtts` 为悠悠君子 2.0，具备英语与指令遵循能力，继续 `seed-tts-2.0`。新混读计划用 `explicit_language: zh-cn`，纯英语用 `en`；省略参数默认中英混读。不启用 SSML 或额外多语种检测，其他音色能力不能由 ID 前缀保证。
- 英文词也保留供应商时间戳；字典转写可能使型号变成多个英语词。保留原词/返回字幕的区别，不伪造原词逐字时间。语流与读音仍需试听，结构检查不等于听感验收。

详见 [官方参数依据与表格式](references/mixed-language.md)。

## 中文校对边界

- 扫描使用单字多读音字典，建议使用词组上下文；包含生僻、古音候选，可能误报或漏报。你仍需阅读全文，不能把词典建议称为“准确识别”或“用户确认”。补充遗漏项直接加入 `readings`。
- 普通轻声助词（如“得、的、了”）优先 `delivery: native`，在阅读稿中保留 `de5`、`le5` 等语境校对标注，不自动发送强制拼音或额外轻声指令。出现真实错读再局部纠音；用户反馈不连贯时，先用原句短样撤掉相关规则做对照，而非不断叠加指令。详见 [轻声与自然语流](references/usage.md#轻声与自然语流)。
- 发音字典支持普通话括号拼音和中英文文本转写；通常从 `readings` 生成拼音规则，也可在片段的 `pronunciation_dict.tone` 加入规则，阅读稿会展示补充字典。文本转写只改变服务端合成，不改原稿；补充规则不能替代位置读音校对。同一段里一个词有两种读法时，发音字典按词而非位置生效。改为不超过 9 字的明确词组，或在自然边界拆段；脚本拒绝冲突与最长匹配导致的覆盖错误。
- 语音指令 `direction` 用中文说明情绪、语气、节奏、重音和音调；引用上文 `reference_text` 只用于理解语境，不进入口播 `text`。脚本将两者与纠音说明合入首条 `context_texts`；上文以明确的“只引用、不朗读”说明传入，不虚构官方独立参数。
- 需要中文方言时使用 `explicit_dialect` 并选择官方标明支持该方言的音色，不同时要求普通话；语音指令也必须选择支持该能力的 2.0 音色，不能仅凭 `zh_` 前缀断言支持。方言示例和代码见 [语音指令与引用上文](references/usage.md#语音指令与引用上文)。普通话拼音不代表方言读音，不把普通话逐字纠音规则机械用于方言。变调不要仅凭逐字拼音自动强制。
- 已授权的可听别名按具体位置作用，保持 `text` 与阅读稿原字；在阅读稿中同时显示实际提交的替代字。`spoken_alias` 必须与已校对拼音一致，并记录 `alias_approved: true`；不能仅为了通过验证自行宣称已获授权。脚本同时附读音指令，把语音指令、引用上文与全部纠音说明合入首条 `context_texts`。新音色或新 take 的实际效果仍需试听。
- `section_id` 按连续段落分组，同一段拆出的片段可使用同一值，换场景时换值；它不是引用正文，也不当作跨请求记忆保证。
- 当前接豆包 TTS 2.0 预置中文音色和已有的声音复刻 2.0 音色，使用 v3 单向 HTTP，支持语音指令、引用上文、方言、发音字典、语速、PCM 转 WAV 和顺序拼接，具体音色能力须验证；不做其他语种保证、录音上传/音色训练、旧代际复刻接口、实时播放、SSML 或原生多人联合合成。多人对白通过各角色片段按顺序合成。无需照搬 Gemini 的供应商层、take 管理或混音框架。

参数依据 [火山官方 HTTP 文档](https://docs.volcengine.com/docs/DoubaoVoice/unidirectional-streaming-text-to-speech-http?lang=zh)。读音校对、请求接线和实际发音是三个独立结果：页面注音不控制合成，合法请求不证明读对，特定音色的一次成功也不能保证其他音色或后续生成。
